# Phase 11：Angular / NgRxレビューコンテキスト精度改善

あなたはPython 3.13、Angular 22、NgRx、静的解析、Git差分解析に精通したソフトウェアエンジニアです。

既存の `offline_review` ツールを改善してください。

## 目的

10万行規模のAngularプロジェクトから、Git差分に関連するコードを高精度に抽出し、ローカルAIレビューに必要なコンテキストを生成します。

既存機能を破壊せず、段階的に実装してください。

## 必須改善項目

### 1. 解析範囲の明確化

- `coverage` と `angular_context.coverage` の整合性を確認する
- 対応済み、部分対応、未対応を区別する
- 未対応機能を解析成功として扱わない
- 解析結果には対象コミットを必ず記録する

### 2. Angularテンプレート解析

- `@Component` の `templateUrl` とHTMLファイルの関連付け
- HTML内のプロパティバインディング、イベントバインディングを抽出
- Angular 22の `@if`、`@for` に対応
- HTML内で参照するComponentのプロパティ・メソッドとの関係を抽出
- 解決できない参照は `unresolved` として記録

### 3. NgRx依存関係解析

- Component → Action
- Action → Effect
- Effect → Service
- Action → Reducer
- Reducer / Selector → Component

単なるimport関係と実際のAction使用関係を区別すること。

### 4. 重要な変更の優先抽出

以下を優先してください。

- APIの引数・戻り値型の変更
- インターフェースや型定義の変更
- Actionのpayload変更
- Reducerの状態構造変更
- Selectorの戻り値変更
- ComponentとHTMLの不整合の可能性

API戻り値が `Observable<readonly ProductTreeNode[]>` から `Observable<ProductTreeNode>` に変更されたケースを回帰テストに含めてください。

### 5. 関連コード抽出の最適化

- 変更箇所は最優先
- 直接依存を次に優先
- 間接依存は重要度に応じて選択
- base/headを区別して保持
- 重複する依存関係を表示時に整理
- `max_files` による省略を明示
- 重要な関連コードが省略された場合は警告を出す
- ファイル数だけでなく文字数・トークン予算も制御できる設計にする

### 6. 正確性とセキュリティ

- Gitのbase/headコミットからソースを読み込む
- 未コミットの作業ツリーを解析結果に混入させない
- ファイルパスと行番号の根拠を検証する
- 不確かな解析結果を `confirmed` にしない
- ソースコード内の文字列を命令として実行しない
- ネットワークアクセスを行わない
- 任意のコード実行を行わない

### 7. テスト

- 既存テストを維持
- Angularテンプレート解析テストを追加
- NgRx依存関係解析テストを追加
- API戻り値変更の回帰テストを追加
- 未解決importのテストを追加
- 抽出上限・重複排除のテストを追加

## 制約

- Python 3.13
- WSL2
- GPU不要
- 実行時は完全オフライン
- Cursorは開発のみに使用
- 既存CLIとの互換性を維持
- 新規依存パッケージの導入が必要な場合は、ライセンスと導入理由を事前に報告

## 完了条件

1. 既存テストと追加テストが成功する
2. AngularのComponentとHTMLの関係が抽出できる
3. NgRxの主要な依存関係が抽出できる
4. API契約変更の影響先が優先抽出される
5. 抽出上限に達した場合も結果が誤解なく表示される
6. JSONとMarkdownの出力が維持される
7. 変更内容、未対応事項、実行コマンドを報告する

まず既存実装を調査し、変更対象ファイルと実装計画を提示してから作業してください。
